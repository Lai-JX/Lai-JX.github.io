    现代 LLM 的 FFN：从 SwiGLU 到 MoE¶

    当前 LLM 的 FFN，可以从两个完全不同层级的“门控”来理解：

    1. FFN 内部的 activation/channel gate：GLU、GEGLU、SwiGLU 等；
    2. FFN 外部的 conditional-compute gate：MoE Router，决定一个 token 进入哪些 expert。

    现在主流架构基本可以画成下面这个谱系：

    Transformer FFN
│
├── Dense FFN
│   ├── Vanilla MLP
│   │   └── Linear → GELU/ReLU → Linear
│   │
│   └── Gated MLP / GLU Family
│       ├── GLU
│       ├── ReGLU
│       ├── GEGLU
│       └── SwiGLU          ← 当前最主流
│
└── Sparse FFN / MoE
    ├── Token-choice Router
    │   ├── Softmax Top-1
    │   ├── Softmax Top-k
    │   └── Sigmoid Top-k
    │
    ├── Expert-choice Router
    │
    └── Expert Architecture
        ├── Large Experts
        ├── Fine-grained Experts
        ├── Shared + Routed Experts
        └── Pure Routed Experts

    其中，今天真正值得重点理解的是 SwiGLU + MoE Router 这两层 gate。

    四种激活函数速览：

    激活函数 公式 核心特征 在 FFN 中的典型用途
    ReLU \(\max(0,x)\) 负值直接归零，计算简单，但在零点不平滑 传统 FFN、ReGLU
    GELU \(x\Phi(x)\) 平滑地抑制负值，保留少量负信息 BERT/GPT 类 FFN、GEGLU
    SiLU / Swish \(x\sigma(x)\) 平滑且非单调，负值被软抑制 SwiGLU；现代 LLM 的主流选择
    Sigmoid \(\sigma(x)=\frac{1}{1+e^{-x}}\) 输出限制在 \((0,1)\)，可直接解释为门控强度，但两端容易饱和 原始 GLU、MoE Router affinity

    可以简单记成：ReLU 是硬截断，GELU 和 SiLU 是平滑软门控，Sigmoid 则直接产生 \(0\) 到 \(1\) 之间的门值。其中，ReLU、GELU 和 SiLU 既可以作为普通 FFN 的激活函数，也可以用于 GLU 的 gate 分支；Sigmoid 则主要承担显式门控作用。

    第一部分：Dense FFN——通道级门控¶

    这一部分关注 FFN 内部的计算：模型如何通过激活函数和 GLU 结构，动态调节每个中间通道的贡献。

    1.1 最传统的 FFN：没有 Gate¶

    原始 Transformer FFN 就是：

    \[ \operatorname{FFN}(x) = W_2\,\phi(W_1x) \]

    通常：

    d_model
   │
   ▼
Linear W1
   │
   ▼
4 × d_model
   │
 GELU/ReLU
   │
   ▼
Linear W2
   │
   ▼
d_model

    例如经典 Transformer、BERT、GPT-2 等都接近这种形式。

    这里没有真正意义上的 gate，只是：

    \[ z_i=\phi\!\left(w_i^{\top}x\right) \]

    每个 hidden channel 单独经过激活函数。

    1.2 GLU：第一次真正引入 FFN Gate¶

    GLU 的核心思想是：

    不只计算一个 feature 分支，而是再计算一个 gate 分支，然后二者逐元素相乘。

    一般形式：

    \[ \boxed{ \operatorname{FFN}(x) = W_{\text{down}} \left[ \phi(W_{\text{gate}}x) \odot W_{\text{up}}x \right] } \]

    结构：

                     ┌── W_gate ── φ ──┐
x ───────────────┤                  × ── W_down ── output
                 └── W_up ─────────┘

    也就是你在 HuggingFace / SGLang / Megatron 代码里经常看到的：

    gate = gate_proj(x)
up   = up_proj(x)

hidden = act(gate) * up

output = down_proj(hidden)

    这里：

    • gate_proj：产生门控值
    • up_proj：产生真正的 feature/value
    • *：逐 channel 相乘
    • down_proj：投影回 hidden size

    Shazeer 系统比较了这一类 GLU 变体，发现 gated FFN 在 Transformer 中相较普通 ReLU/GELU FFN 可以取得更好的效果。(arXiv)

    1.3 GLU 家族：同一结构，不同门控函数¶

    GLU 家族都包含两个并行分支：

    • gate 分支：计算 \(\phi(W_gx)\)，决定各通道通过多少信息；
    • value 分支：计算 \(W_ux\)，提供实际传递的特征。

    两个分支逐元素相乘，再通过 \(W_d\) 投影回模型维度：

    \[ \boxed{ \operatorname{FFN}_{\phi}(x) =W_d\left[ \phi(W_gx)\odot W_ux \right] } \]

    因此，各种 GLU 变体共享相同结构，核心区别是 gate 分支所使用的函数 \(\phi\)。

    变体 门控函数 \(\phi(a)\) 中间表示 \(z\) 特点与典型应用
    GLU \(\sigma(a)\) \(\sigma(W_gx)\odot W_ux\) 最原始的 GLU；门值限制在 \((0,1)\)
    Bilinear \(a\) \((W_gx)\odot W_ux\) 不使用非线性门控，主要作为对照
    ReGLU \(\operatorname{ReLU}(a)\) \(\operatorname{ReLU}(W_gx)\odot W_ux\) 直接截断负门控值
    GEGLU \(\operatorname{GELU}(a)\) \(\operatorname{GELU}(W_gx)\odot W_ux\) 平滑门控；Gemma 等模型采用
    SwiGLU \(\operatorname{SiLU}(a)\) \(\operatorname{SiLU}(W_gx)\odot W_ux\) 平滑且非单调；现代 LLM 中最常见

    这里需要特别区分：原始 GLU 专指使用 Sigmoid 的版本；广义的 “GLU family” 才包括 ReGLU、GEGLU 和 SwiGLU 等变体。

    这些变体由 Shazeer 的 GLU Variants 工作进行了系统比较。(arXiv) 当前最值得重点关注的是 GEGLU 和 SwiGLU，后两节将分别展开。

    1.4 GEGLU¶

    GEGLU：

    \[ \boxed{ z= \operatorname{GELU}(W_gx) \odot W_ux } \]

    然后：

    \[ y=W_dz \]

    Gemma 系列就是一个典型代表。例如 Gemma 2 的 technical report 明确使用 GeGLU 作为 FFN non-linearity。(arXiv)

    因此你可以简单记：

    Gemma
   ↓
GeGLU

    1.5 SwiGLU：现在最主流的 Dense FFN¶

    SwiGLU：

    \[ \boxed{ z= \operatorname{SiLU}(W_gx) \odot W_ux } \]

    其中：

    \[ \operatorname{SiLU}(x)=x\sigma(x) \]

    所以完整写出来：

    \[ \operatorname{SwiGLU}(x) = \left[ (W_gx)\sigma(W_gx) \right] \odot (W_ux) \]

    最后：

    \[ y=W_d\operatorname{SwiGLU}(x) \]

    架构：

                         gate_proj
                         │
                         ▼
                       SiLU
                         │
                         ▼
x ───────────────────────×──────► down_proj ──► y
│                        ▲
│                        │
└────── up_proj ─────────┘

    当前很多主流开源 LLM 都使用 SwiGLU。例如 Qwen3 的 dense 模型明确采用 SwiGLU；Mixtral 的每个 MoE expert 本身也是一个 SwiGLU FFN；DeepSeek-V3 的 MoE expert 内部同样使用 SwiGLU。(arXiv)

    所以从工程角度讲：

    现代 LLM 的“标准 FFN”已经基本从 Linear → GELU → Linear 演化成了 gate_proj + up_proj → SwiGLU → down_proj。

    1.6 为什么 SwiGLU 有三个 Linear？¶

    普通 FFN：

    \[ x\rightarrow W_1\rightarrow \phi\rightarrow W_2 \]

    只有两个矩阵：

    W_up
W_down

    SwiGLU：

    W_gate
W_up
W_down

    三个矩阵。

    假设：

    \[ d_{\text{model}}=d \]

    传统 FFN intermediate：

    \[ d_{\mathrm{ff}}=4d \]

    参数量大约：

    \[ d(4d)+(4d)d =8d^2 \]

    而 SwiGLU 有三个矩阵。如果 intermediate dimension 为 (m)：

    \[ dm+dm+md=3dm \]

    为了参数量接近：

    \[ 3dm\approx8d^2 \]

    所以：

    \[ \boxed{ m\approx\frac83d\approx2.67d } \]

    这就是为什么你会发现很多 LLaMA-style 模型不是：

    4096 → 16384 → 4096

    而是类似：

    4096
  ├─ gate → ~11000
  └─ up   → ~11000
              ↓
            multiply
              ↓
         ~11000 → 4096

    intermediate size 变小了，但多了一条 gate branch。

    1.7 SwiGLU 的 Gate 到底在控制什么？¶

    这是理解 SwiGLU 最重要的一点。

    设：

    \[ g=\operatorname{SiLU}(W_gx) \]
    \[ v=W_ux \]

    则：

    \[ z_i=g_i v_i \]

    也就是说：

    每一个 FFN intermediate channel 都有自己的 gate。

    比如：

    value:
[ 2.1, -1.3, 0.7, 5.2 ]

gate:
[ 0.9,  0.01, 0.8, 0.02 ]

               ↓ elementwise ×

output:
[ 1.89, -0.013, 0.56, 0.104 ]

    第二、第四个 channel 基本被抑制掉了。

    所以 SwiGLU 可以理解成：

    \[ \boxed{ \text{input-dependent channel gating} } \]

    即：

    不同 token 激活不同程度的 FFN neuron/channel。

    1.8 为什么 SwiGLU 不等于稀疏计算？¶

    这一点非常容易混。

    虽然：

    \[ g_i\approx0 \]

    可能让某个 channel 的最终贡献很小，但 GPU 实际上通常还是已经算完：

    \[ W_gx \]

    和：

    \[ W_ux \]

    了。

    所以：

    SwiGLU

token
  │
  ├──► 所有 gate channels 都算
  │
  └──► 所有 up channels 都算
               │
               ▼
              ×

    本质仍然是 Dense GEMM。

    所以 SwiGLU gate 是：

    \[ \textbf{activation gating} \]

    而不是：

    \[ \textbf{conditional computation} \]

    这和 MoE 完全不同。

    第二部分：Sparse FFN——Expert 级门控¶

    这一部分将门控粒度从 channel 提升到整个 FFN Expert：Router 为每个 token 选择实际参与计算的 Expert，从而实现条件计算。

    2.1 MoE Router：从通道门控到 Expert 门控¶

    MoE 是在 FFN 级别进行 gate。

    普通 Dense：

    token x
   │
   ▼
 FFN
   │
   ▼
output

    MoE：

                       ┌── Expert 0
                   │
                   ├── Expert 1
token ── Router ───┼── Expert 2
                   │
                   ├── ...
                   │
                   └── Expert N

    router 根据 token：

    \[ x_t \]

    计算每个 expert 的 score：

    \[ s_{t,i}=f(x_t,e_i) \]

    然后选：

    \[ \operatorname{TopK}(s_t) \]

    最终：

    \[ y_t =\sum_{i\in\operatorname{TopK}(s_t,K)} g_{t,i}E_i(x_t) \]

    这里：

    \[ E_i \]

    本身通常又是一个 SwiGLU FFN。

    所以现在 MoE 里面其实存在两层 gate：

                    ┌──────── MoE Router Gate ────────┐
                │                                  │
token ──────────┼──► Expert #7                    │
                │       │                         │
                │       ├─ SwiGLU channel gate    │
                │       │                         │
                │       └─ output                 │
                │                                  │
                └──► Expert #23
                        │
                        ├─ SwiGLU channel gate
                        │
                        └─ output

    一个是：

    \[ \boxed{\text{token → expert}} \]

    一个是：

    \[ \boxed{\text{token → channel}} \]

    2.2 经典路由：Softmax Top-k¶

    经典形式：

    \[ r=W_rx \]

    得到：

    \[ r\in\mathbb R^{N_{\text{expert}}} \]

    然后：

    \[ p_i= \frac{e^{r_i}} {\sum_j e^{r_j}} \]

    选：

    \[ S=\operatorname{TopK}(p,K) \]

    最终：

    \[ y=\sum_{i\in S}p_iE_i(x) \]

    例如：

    router logits

E0  -1.2
E1   0.2
E2   2.3  ← select
E3  -0.7
E4   1.9  ← select
E5   0.1
E6  -0.2
E7   0.8

Top-2 → E2 + E4

    Mixtral 就是非常典型的 Top-2 expert routing：每层有 8 个 FFN experts，每个 token 选择其中两个，而且 expert 自身使用 SwiGLU。(arXiv)

    2.3 Top-1 路由：Switch Transformer¶

    另一种极端是：

    \[ K=1 \]

    即每个 token 只跑一个 expert：

    token
 │
Router
 │
 ▼
Expert 37
 │
 ▼
output

    这就是 Switch Transformer 推广的设计。

    优势：

    \[ \text{最少 FFN compute} \]

    缺点则是：

    • router 更容易负载不均；
    • expert capacity 更难控制；
    • 单 expert 决策更加离散。

    Switch Transformer 的核心就是将经典 MoE routing 简化到 Top-1。(arXiv)

    2.4 DeepSeek-V3：Sigmoid Top-k Gate¶

    DeepSeek-V3 有一个很值得注意的变化。

    经典 router 很多是：

    \[ s_i=\operatorname{softmax}\!\left(x^{\top}e_i\right) \]

    DeepSeek-V3 使用：

    \[ \boxed{ s_{i,t} =\operatorname{Sigmoid} \!\left(u_t^{\top}e_i\right) } \]

    然后进行 Top-K：

    \[ S_t=\operatorname{TopK}(s_t,K) \]

    被选中的 gating weight 再归一化：

    \[ g_{i,t} =\frac{s_{i,t}} {\sum_{j\in S_t}s_{j,t}} \]

    DeepSeek-V3 technical report 明确说明其相较 DeepSeek-V2 使用 sigmoid affinity，再在被选中的 experts 之间归一化。(arXiv)

    所以：

               Router
             │
             ▼
        linear scores
             │
          sigmoid
             │
           Top-K
             │
      selected experts
             │
         normalize

    2.5 为什么从 Softmax Router 转向 Sigmoid？¶

    Softmax 有一个性质：

    \[ \sum_i p_i=1 \]

    也就是说不同 experts 的 score 天然互相竞争。

    假设：

    Expert A score ↑

    那么其他 expert 的概率自然会降低。

    Sigmoid 则是：

    \[ s_i=\sigma(r_i) \]

    每个 expert affinity 独立：

    E1: 0.91
E2: 0.89
E3: 0.05
E4: 0.02

    理论上可以同时认为：

    E1 非常适合
E2 也非常适合

    最后再通过 Top-K 决定选择谁。

    因此两种思想略有不同：

    Softmax:
“这些 expert 中谁最适合？”

Sigmoid:
“每个 expert 分别有多适合这个 token？”

    2.6 Shared Expert 与 Routed Expert¶

    这是现代 MoE FFN 架构的另一个重要分支。

    传统 MoE：

                  Routed
token ──────► E1
       ─────► E7
       ─────► E23

    DeepSeekMoE 引入：

                           ┌── Shared Expert ─── always
token ─────────────────┤
                       │
                       │ Router
                       ├── Routed Expert 7
                       ├── Routed Expert 31
                       └── ...

    形式是：

    \[ h_t' =u_t + \underbrace{ \sum_i FFN_i^{(s)}(u_t) }_{\text{shared experts}} + \underbrace{ \sum_i g_{i,t}FFN_i^{(r)}(u_t) }_{\text{routed experts}} \]

    设计动机是让：

    • Shared expert 学通用知识；
    • Routed experts 更专门化。

    DeepSeekMoE 明确提出了 fine-grained expert segmentation + shared expert isolation；DeepSeek-V3 延续了这一架构。(arXiv)

    2.7 Fine-grained Experts¶

    这是 DeepSeekMoE 非常重要的一步。

    传统 MoE 假设：

    FFN width = 14336

E0 = 一个完整 14336 FFN
E1 = 一个完整 14336 FFN
...

    DeepSeekMoE 的思路更接近：

    一个大 expert
      ↓
拆成多个小 expert

Expert0: smaller FFN
Expert1: smaller FFN
Expert2: smaller FFN
...

    于是原本：

    \[ N\text{ experts},\quad \operatorname{TopK} \]

    可以变成：

    \[ mN\text{ smaller experts},\quad \operatorname{Top}(mK) \]

    在维持近似计算量的情况下，expert 组合数量显著增加。

    论文将其称为 fine-grained expert segmentation。(arXiv)

    可以直观理解成：

    粗粒度：

token → [数学专家]

细粒度：

token
 ├→ [算术]
 ├→ [符号推理]
 ├→ [代码]
 └→ [英语]

    组合能力更强。

    2.8 Shared Expert 并不是必需的¶

    这也是目前不同模型路线的一个明显分叉。

    例如 Qwen3 MoE 使用：

    \[ 128\text{ experts} \]

    每个 token 激活：

    \[ 8\text{ experts} \]

    并采用 fine-grained expert segmentation，但 Qwen3 取消了 shared experts。(arXiv)

    因此现在可以看到两种思路：

    DeepSeek-style

Shared Expert
    +
Top-K Routed Experts

    vs.

    Qwen3-style

Top-K Routed Experts only

    它们解决的 trade-off 不同：

    • Shared expert：减少 routed expert 重复学习通用能力；
    • Pure routed：结构更统一，也避免 shared expert 成为永远激活的固定计算。

    2.9 Router 的另一个维度：谁选择谁？¶

    绝大部分主流 autoregressive LLM 用的是：

    Token Choice¶

    Token A ──► choose E3, E7
Token B ──► choose E1, E3
Token C ──► choose E3, E8

    即：

    \[ \boxed{\text{Token chooses Experts}} \]

    问题是：

    E3 ← 10000 tokens
E5 ← 100 tokens

    可能严重负载不均。

    还有一种反过来的方法：

    Expert Choice¶

    Expert 0 → choose its favorite tokens
Expert 1 → choose its favorite tokens
Expert 2 → choose its favorite tokens

    即：

    \[ \boxed{\text{Expert chooses Tokens}} \]

    这样每个 expert 可以规定固定容量，因此天然更容易平衡负载。Expert Choice Routing 论文就是从这个角度提出这一设计。(arXiv)

    不过当前主流 autoregressive 大模型仍以 token-choice Top-k 为主。

    2.10 Load Balancing 也是 Gate 架构的一部分¶

    MoE 最大的问题之一就是：

    \[ \text{Router Collapse} \]

    比如：

    E1 ███████████████████████
E2 ██
E3 █
E4 █████

    所有 token 都喜欢几个热门 experts。

    早期方法通常加：

    \[ L_{\text{balance}} \]

    迫使 expert utilization 更均匀。

    但问题在于：

    \[ L_{\text{total}} =L_{\text{LM}} + \lambda L_{\text{balance}} \]

    可能干扰语言模型本来的优化目标。

    DeepSeek-V3 的方法比较特别：

    给每个 expert 一个动态 bias：

    \[ b_i \]

    router 选择 expert 时使用：

    \[ s_i+b_i \]

    但是最终 expert output 的权重仍使用原始：

    \[ s_i \]

    如果 expert (i) 过载：

    \[ b_i\downarrow \]

    如果负载不足：

    \[ b_i\uparrow \]

    也就是：

                   affinity s_i
                    │
          ┌─────────┴─────────┐
          │                   │
     s_i + bias_i            s_i
          │                   │
       Top-K               combine
          │                   ▲
          └──── experts ──────┘

    这是 DeepSeek-V3 所谓的 auxiliary-loss-free load balancing 核心机制。(arXiv)

    2.11 现代 MoE FFN 的完整结构¶

    如果拿一个典型的现代 MoE 模型抽象：

                             Transformer Block
                                │
                              RMSNorm
                                │
                                ▼
                            Attention
                                │
                              Residual
                                │
                              RMSNorm
                                │
                                ▼
                     ┌──────── Router ────────┐
                     │                        │
                     ▼                        ▼
                  Expert 7                 Expert 31
                     │                        │
           ┌─────────┴──────┐       ┌─────────┴──────┐
           │                │       │                │
        W_gate            W_up    W_gate            W_up
           │                │       │                │
          SiLU              │      SiLU              │
           │                │       │                │
           └────── × ───────┘       └────── × ───────┘
                  │                         │
                W_down                    W_down
                  │                         │
                  └──────── weighted sum ──┘
                               │
                            Residual

    因此里面实际上有：

    \[ \boxed{ \text{Router Gate} } \]

    *

    \[ \boxed{ \text{SwiGLU Gate} } \]

    两个不同尺度的 gating。

    总结：用门控粒度统一理解 FFN¶

    我觉得这是最容易建立整体认知的方法：

    Gate 粒度 决定什么 是否减少 GEMM
    ReLU/GELU neuron neuron activation 通常否
    GLU channel channel 强弱 否
    GEGLU channel channel 强弱 否
    SwiGLU channel FFN feature 强弱 否
    MoE Router expert 哪些 FFN 被运行 是
    Top-1 Router expert 1 个 expert 是
    Top-k Router expert k 个 experts 是
    Shared Expert expert 永远执行的 FFN 否
    Expert Choice token/expert expert 接收哪些 token 是

    所以可以把整个 FFN 的发展路线总结成：

    Vanilla FFN
    │
    │  improve nonlinearity
    ▼
GELU FFN
    │
    │  introduce channel-wise gating
    ▼
GLU / GEGLU
    │
    ▼
SwiGLU
    │
    │  introduce parameter-level conditional compute
    ▼
Sparse MoE
    │
    ├── Top-1 / Top-k
    ├── fine-grained experts
    ├── shared experts
    ├── sigmoid routing
    └── aux-loss-free balancing

    最值得记住的三种结构¶

    我建议直接记：

    ① Dense SwiGLU

    \[ \boxed{ W_d\left[ \operatorname{SiLU}(W_gx)\odot W_ux \right] } \]

    LLaMA/Qwen 等这一大类模型的核心 FFN 思路，Qwen3 明确采用这种架构。(arXiv)

    ② Classic Sparse MoE

    \[ \boxed{ \sum_{i\in\operatorname{TopK}} g_iE_i(x) } \]

    Mixtral 是很典型的 Top-2 + SwiGLU experts。(arXiv)

    ③ DeepSeek-style MoE

    \[ \boxed{ E_{\rm shared}(x) + \sum_{i\in\operatorname{TopK}}g_iE_i(x) } \]

    并叠加：

    fine-grained experts
+ sigmoid gating
+ Top-K
+ shared experts
+ auxiliary-loss-free balancing

    这是目前非常有代表性的一套 MoE FFN 设计。(arXiv)

    如果你接下来是在深入学 LLM 架构本身，我建议下一步直接从 SwiGLU 的 gate_proj / up_proj / down_proj 到 DeepSeek/Qwen 的 MoE router 连起来看；这能把 Dense FFN → MoE FFN 的演化逻辑完整串起来。
