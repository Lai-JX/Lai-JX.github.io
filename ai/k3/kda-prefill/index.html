    KDA Prefill：Chunkwise 与 FlashKDA¶

    KDA 数学上是 RNN 式递推，但 prefill 如果真的按 token 一个一个更新 \(S_t\)，GPU 利用率会很差。

    Kimi K3 的解决方案不是把递推彻底消掉，而是把它改写成：

    chunk 之间递推，chunk 内部并行。

    更具体地说，它把一个 chunk 内原本 \(C\) 次顺序的 state update，等价变换成几次 矩阵乘法 + 三角矩阵运算，于是能交给 Tensor Core。K3 论文明确写的是 “recurrent across chunks and parallel within each chunk”。(arXiv)

    1. 先看最原始的 KDA：为什么是串行的¶

    单个 head 的 KDA state 是

    \[ S_t\in\mathbb{R}^{d_k\times d_v} \]

    更新公式：

    \[ S_t = (I-\beta_t k_t k_t^\top) \operatorname{Diag}(\alpha_t)S_{t-1} + \beta_t k_t v_t^\top \]

    然后

    \[ o_t=S_t^\top q_t. \]

    可以简写成：

    \[ S_t=M_t S_{t-1}+B_t \]

    其中

    \[ M_t=(I-\beta_tk_tk_t^\top)\operatorname{Diag}(\alpha_t), \qquad B_t=\beta_t k_t v_t^\top. \]

    于是：

    S0
 ↓ token 1
S1
 ↓ token 2
S2
 ↓ token 3
S3
 ...

    显然 \(S_2\) 必须等 \(S_1\)，\(S_3\) 必须等 \(S_2\)。

    如果 1M token 真这么算，就是 1M 级别的串行依赖链。K3 论文也直接指出，KDA state 的 serial dependence 和 GPU 喜欢的宽并行天然冲突。(arXiv)

    2. Chunkwise 的第一步：把 C 个 token 一次展开¶

    假设一个 chunk 有 \(C\) 个 token：

    \[ 1,2,\ldots,C \]

    chunk 输入 state 是 \(S_{[t]}\)。

    递推展开：

    \[ S_1=M_1S_{[t]}+B_1 \]
    \[ S_2=M_2M_1S_{[t]}+M_2B_1+B_2 \]
    \[ S_3=M_3M_2M_1S_{[t]} +M_3M_2B_1+M_3B_2+B_3 \]

    所以任意第 \(r\) 个位置都可以写成

    \[ S_r=P_rS_{[t]}+H_r. \]

    其中

    \[ P_r=\prod_{i=1}^{r}M_i \]

    表示“chunk 入口 state 经过前 \(r\) 个 token 后变成什么”，而 \(H_r\) 表示这 \(r\) 个 token 自己写进去的新信息。

    这一步很重要：

    原来我们想的是：

    先算 \(S_1\)，才能算 \(S_2\)。

    现在换了个视角：

    如果我能直接算出 \(P_r,H_r\)，那么 $$ S_r=P_rS_{\rm in}+H_r $$ 每个 \(r\) 就不一定需要逐 token 递推。

    Kimi Linear 的推导就是从这里开始的。

    3. 但直接算 \(P_r=M_r\cdots M_1\) 还是不行¶

    如果 \(M_t\) 是任意 \(d_k\times d_k\) 矩阵，那么算

    \[ M_rM_{r-1}\cdots M_1 \]

    一样很贵。

    KDA 恰好有特殊结构：

    \[ M_t = (I-\beta_tk_tk_t^\top) \operatorname{Diag}(\alpha_t). \]

    它本质是：

    Diagonal + Rank-1

    这就是论文里强调的 DPLR / WY representation 能发挥作用的原因。Kimi Linear 利用这个特殊结构，把一串 rank-1 transformation 压缩成一个适合 dense matrix multiplication 的表示。

    4. 先把 decay 累积起来¶

    定义从 token \(i\) 到 token \(j\) 的 channel-wise decay：

    \[ \gamma^{i\rightarrow j} = \prod_{r=i}^{j}\alpha_r. \]

    特别定义：

    \[ \gamma^r=\gamma^{1\rightarrow r}. \]

    把一个 chunk 所有累计 decay 堆起来：

    \[ \Gamma= \begin{bmatrix} \gamma^1\\ \gamma^2\\ \vdots\\ \gamma^C \end{bmatrix} \in\mathbb{R}^{C\times d_k}. \]

    因为 \(\alpha_t\) 是 channel-wise 的，所以这里不是一个 scalar decay，而是每个 channel 各自累乘。K3 就是按照这个形式定义 \(\Gamma\) 的。(arXiv)

    5. 最关键的一步：UT/WY transform¶

    Kimi Linear 推导出了两个 chunk 内的矩阵：

    \[ W\in\mathbb{R}^{C\times d_k}, \qquad U\in\mathbb{R}^{C\times d_v}. \]

    它们把原先那堆

    \[ M_rM_{r-1}\cdots \]

    的 rank-1 更新全部吸收掉。

    具体来说，可以构造一个 \(C\times C\) 的下三角系统：

    \[ \mathcal M = \left[ I+ \operatorname{StrictTril} \left( \operatorname{Diag}(\beta) (\Gamma\odot K) (K/\Gamma)^\top \right) \right]^{-1} \operatorname{Diag}(\beta), \]

    然后

    \[ W=\mathcal M(\Gamma\odot K), \]
    \[ U=\mathcal M V. \]

    这其实是整个 chunkwise KDA 的数学核心。

    注意这里真正求逆/solve 的东西是：

    \[ C\times C \]

    而不是

    \[ d_k\times d_k. \]

    Kimi Linear 称这里为 UT transform，它正是为了把原来 sequential 的 \(w_t,u_t\) recurrence 转成适合矩阵运算的形式。

    6. 这样之后，一个 chunk 的所有 output 就能一次算了¶

    这是最值得记住的公式。

    先定义：

    \[ \widetilde V = U-WS_{[t]}. \]

    其中

    \[ W S_{[t]} \quad\Rightarrow\quad (C\times d_k)(d_k\times d_v) \]

    本身就是一个 GEMM。

    然后计算一个 chunk 内的 causal matrix：

    \[ A = \operatorname{Tril} \left[ (Q\odot\Gamma) (K/\Gamma)^\top \right] \in\mathbb{R}^{C\times C}. \]

    最终：

    \[ \boxed{ O_{[t]} = (\Gamma\odot Q)S_{[t]} + A\widetilde V } \]

    K3 论文把两项明确标成：

    \[ \underbrace{(\Gamma\odot Q)S_{[t]}}_{\text{inter-chunk}} + \underbrace{A\widetilde V}_{\text{intra-chunk}}. \]

    (arXiv)

    这个公式非常漂亮。

    第一项：处理前面所有 chunk¶

    \[ (\Gamma\odot Q)S_{[t]} \]

    \(S_{[t]}\) 已经压缩了前面所有历史：

    chunk 0
chunk 1
...
chunk t-1
    ↓
  S_[t]

    当前 chunk 里的所有 \(C\) 个 query：

    \[ Q_1,\ldots,Q_C \]

    一次矩阵乘：

    \[ (C\times d_k)(d_k\times d_v) \]

    就全部读取前面的历史。

    所以不是：

    q1 读 state
q2 读 state
q3 读 state
...

    而是：

            S_in
         │
[ q1 ]
[ q2 ]  │
[ q3 ] ─┼── GEMM ──> C 个 output
[ ...]
[ qC ]

    第二项：处理当前 chunk 内部¶

    \[ A\widetilde V \]

    其中：

    \[ A= \operatorname{Tril} \left[ (Q\odot\Gamma)(K/\Gamma)^\top \right]. \]

    这已经非常像一个 local causal attention 了。

    比如 \(C=4\)：

    \[ A= \begin{bmatrix} a_{11}&0&0&0\\ a_{21}&a_{22}&0&0\\ a_{31}&a_{32}&a_{33}&0\\ a_{41}&a_{42}&a_{43}&a_{44} \end{bmatrix}. \]

    然后：

    \[ \begin{bmatrix} o_1\\ o_2\\ o_3\\ o_4 \end{bmatrix} = A \begin{bmatrix} \tilde v_1\\ \tilde v_2\\ \tilde v_3\\ \tilde v_4 \end{bmatrix}. \]

    所以 4 个 token 的 output 一次 GEMM 全算出来。

    Tril 保证 causal。K3 特别说明对角线也要保留，因为 \(o_t\) 读取的是当前 token 更新之后的 \(S_t\)，因此 token (t) 可以看到自己。(arXiv)

    7. 那下一个 chunk 的 state 怎么得到？¶

    同样不需要把这个 chunk 再逐 token replay 一遍。

    chunk 结束后的 state 可以直接写成：

    \[ \boxed{ S_{[t+1]} = \operatorname{Diag}(\gamma^C)S_{[t]} + (\Gamma\odot K)^\top \left(U-WS_{[t]}\right) } \]

    也就是：

    S_[t]
  │
  │   chunk t 的 Q K V α β
  │             │
  └─────────────┼── dense GEMMs
                ↓
             S_[t+1]

    这是 Kimi Linear Eq. 8 的 chunk-level state update。

    因此 dependency 变成：

    原始 recurrent：

S0 → S1 → S2 → S3 → ... → S1024
      每个 token 一次串行


chunkwise，假设 C=16：

S_chunk0
   ↓
chunk 0 内 16 token 并行
   ↓
S_chunk1
   ↓
chunk 1 内 16 token 并行
   ↓
...

    串行链从 1024 次变成大约：

    \[ 1024/16=64 \]

    次 chunk-level state propagation。

    8. 所以 chunkwise 并不是「所有 chunk 都并行」¶

    这里非常容易产生误解。

    标准 chunkwise KDA：

    \[ \boxed{ \text{parallel within chunk} \quad+\quad \text{recurrent across chunks} } \]

    而不是：

    \[ \text{all chunks parallel}. \]

    K3 论文甚至专门指出，这仍然会存在问题：

    chunk 内并行，但 chunk 间 serial；如果天真地交替执行两部分，serial propagation 时很多 SM 还是会空闲。

    因此 K3 后面又专门设计了 FlashKDA。(arXiv)

    9. K3 实际的 FlashKDA 又做了一层优化¶

    Moonshot 开源的 FlashKDA v1 把计算拆成两个 kernel。

    K1：token/chunk parallel¶

    grid 大致是：

    \[ N\times H\times N_{\rm chunks}. \]

    所有 chunk 都可以同时做那些不依赖 incoming state 的工作，包括 gate activation、Q/K normalization、decay、chunk 内矩阵构造以及小型 triangular inverse。(GitHub)

    可以理解成：

    chunk 0 ──> Γ0,U0,W0,...
chunk 1 ──> Γ1,U1,W1,...
chunk 2 ──> Γ2,U2,W2,...
chunk 3 ──> Γ3,U3,W3,...
   ↑          ↑
全部可以并行准备

    K2：head-parallel recurrence¶

    然后真正涉及

    \[ S_{[t]} \rightarrow S_{[t+1]} \]

    的部分才按 chunk 推进：

    head 0: S0 → chunk0 → S1 → chunk1 → S2 ...
head 1: S0 → chunk0 → S1 → chunk1 → S2 ...
head 2: ...
...

    FlashKDA 官方 deep dive 描述为：

    • K1：token-parallel，grid = N × H × num_chunks
    • K2：head-parallel，grid = N × H

    把这两个并行维度拆开后，可以分别调度、优化，避免一个 fused kernel 被低并行度的 recurrence 拖住。官方报告称这种拆分相对于早期单 kernel 方案带来了至少 15% 的端到端提升。(GitHub)

    所以从 GPU 角度看，实际结构更像：

                     K1: massively parallel
        ┌──────────────┬──────────────┬──────────────┐
        │   chunk 0    │   chunk 1    │   chunk 2    │ ...
        │ Γ,U,W,A prep │ Γ,U,W,A prep │ Γ,U,W,A prep │
        └──────────────┴──────────────┴──────────────┘
                 ↓           ↓             ↓

                    K2: recurrence
S0 ──> [chunk 0] ──> S1 ──> [chunk 1] ──> S2 ──> ...
         GEMM                  GEMM
      16 token out         16 token out
       一次得到              一次得到

    K3 论文称其为“overlaps intra-chunk computation with cross-chunk state propagation”。(arXiv)

    10. K3 为什么特别适合 16-token chunk？¶

    这里是 K3 相比原始 Kimi Linear 的一个很关键的改动。

    KDA 公式里有：

    \[ K/\Gamma. \]

    但

    \[ \Gamma=\prod\alpha_t, \qquad 0<\alpha_t<1. \]

    序列稍微长一点，\(\Gamma\) 可能非常小：

    \[ 1/\Gamma\rightarrow \infty, \]

    BF16 可能 overflow。

    Kimi Linear 原来因此还要做 log-space 和 secondary 16-token tiling，而且 diagonal tile 不能完全走普通 dense Tensor Core path。K3 把 log-decay 改成有下界：

    \[ g_t = g_{\min} \operatorname{Sigmoid}(e^{A}z_t), \qquad g_{\min}=-5, \]
    \[ \alpha_t=e^{g_t}. \]

    所以：

    \[ \alpha_t>e^{-5}. \]

    对于 16 token：

    \[ \log \Gamma > -5\times16=-80, \]

    因此：

    \[ 1/\Gamma < e^{80}, \]

    仍然落在 BF16 dynamic range 里。于是 包括 diagonal causal tile 在内，都能直接走 dense Tensor Core matmul。这是 K3 论文 Figure 3 强调的系统协同设计。(arXiv)

    而 Moonshot 当前 FlashKDA v1 的公开实现确实选择了：

    \[ \boxed{C=16} \]

    官方给的三个原因就是 BF16 数值范围、\(16\times16\) inverse 很便宜，以及能很好映射到 NVIDIA MMA。(GitHub)

    11. 但 1M context 时，64K 个 chunk 不是还是串行吗？¶

    对。

    这也是 K3 又做 intra-device context parallelism 的原因。

    这是比普通 chunkwise 更进一步的设计。

    关键观察是，一个 segment 对 state 的作用始终可以写成 affine transform：

    \[ \boxed{ S_{\rm out}=M_{\rm seg}S_{\rm in}+\widetilde S_{\rm seg} } \]

    其中：

    • \(M_{\rm seg}\)：segment 对进入 state 的累计变换；
    • \(\widetilde S_{\rm seg}\)：假设 \(S_{\rm in}=0\)，这个 segment 自己生成的 state。

    这两个东西都只依赖 segment 自己的 token，所以即使不知道真正的 \(S_{\rm in}\)，不同 segment 也可以先并行计算：

    segment 0 → (M0, B0)
segment 1 → (M1, B1)
segment 2 → (M2, B2)
segment 3 → (M3, B3)
             ↑
        可以并行

    然后利用 affine transform 的结合律做 prefix scan：

    \[ (M_2,B_2)\circ(M_1,B_1) = (M_2M_1,\;M_2B_1+B_2). \]

    这样就可以恢复每个 segment 真正的 incoming state。

    K3 论文明确说，它们在单个 GPU 内把超长序列分给多个 SM，先并行计算 segment transitions，再 compose 恢复每段精确 initial state；跨设备的 KDA Context Parallelism 也是相同思想，只是需要交换这些固定大小的 transition/state fragments。(arXiv)

    最后可以把 K3 prefill 的并行化理解成三层¶

                        1M-token sequence
                           │
        ┌──────────────────┴─────────────────┐
        │       segment / context parallel    │
        │  各 segment transition 可先并行算   │
        └──────────────────┬─────────────────┘
                           │ prefix scan
                    得到各 segment S_in
                           │
               ┌───────────┴───────────┐
               │      chunk level       │
               │ S0 → S1 → S2 → ...    │
               │   仍有 recurrent       │
               └───────────┬───────────┘
                           │
                     每个 C=16 chunk
                           │
              ┌────────────┴────────────┐
              │    token-level parallel  │
              │ QK^T / AV / WS 等 GEMM  │
              │ 16 个 output 一次算出   │
              └─────────────────────────┘

    所以如果只记一句：

    \[ \boxed{ \begin{aligned} \text{KDA chunkwise:}\quad \text{token-level recurrence} &\rightarrow \text{chunk-level recurrence} \\ &\quad +\ \text{intra-chunk causal GEMM} \end{aligned} } \]

    它不是消灭 recurrence，而是把 recurrence 的粒度放大，同时把绝大部分 FLOPs 转换成 GPU 最擅长的 dense matmul。K3 再用 FlashKDA 的两阶段调度和 segment-level context parallelism，把剩余的 chunk 间串行进一步隐藏/并行化。(arXiv)

    如果你接下来在看 K3/FLA 的实际代码，那么最值得继续往下对照的就是 chunk_kda 中 \(U,W,\Gamma\) 是怎么生成的，以及 FlashKDA 的 K1/K2 分别对应上面哪几个公式。这两部分一对应起来，KDA 的 kernel 实现基本就通了。
